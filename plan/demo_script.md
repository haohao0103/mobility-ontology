# 本体系统演示脚本（6 主线 + 4 深挖 · 本体排他性验证）

> 目标：**20 分钟让领导看懂「本体系统有哪些东西」+「交互式问题能否展示价值」**
> 页面：`http://127.0.0.1:8765/profile/order-ontology`（本地 8765；STG `stg-121` 不可达）
> 实现：`web/order-ontology.html` 的 6 主线场景 + 4 深挖场景（`tier: main|deep`）
> 计划依据：[demo-interactive-plan.md](demo-interactive-plan.md)
> 自检：`python scripts/browser_rehearsal.py`（真实点击 6 主线，每步断言）+ `demo_gate.py --fast --strict`

---

## 0. 开场 30 秒

> 「这系统的核心不是一张表，是一个**本体**：把『运单、费用项、定价规则、报价单、结算单』
> 这些业务概念，连同**关系、规矩、状态流转、能做的动作、谁有权限看**定义在一处。
> 接下来六个问题，每个我都会做同一件事：**先按本体算一遍，再改一行本体声明，看结果怎么翻转**。
> 最后把同一份数据直接丢给大模型，看它和我们差在哪。」

不要说"这是图数据库"（会被理解成可视化工具），要说**"让机器理解并执行业务规则的本体"**。

## 1. 六条主线（页面默认展示）

每条主线都必须走同一套闭环：**本体声明 → 真实接口 → INPUT/OUTPUT 可见 → 抽掉声明 → 结果翻转 → 收束**。

### M1 承重：同一笔费用，换一版本本体，结论会变吗？

| 项 | 内容 |
|---|---|
| 开场问 | 代码一行不改，只把免费等候从 30 改成 20 分钟，诊断结论会不会变？ |
| 本体声明 | `pricing.waiting.free_minutes = 30`；版本 `1.1.0-demo` 改为 20 |
| 正向 | `GET /waybills/{wb}/fee-analysis` → 免费 30 分钟、应计 12 元、差异 38 |
| **负向翻转** | `?version=1.1.0-demo` → 结论变 BLOCKER（旧版缺可执行 AST） |
| 确定性补强 | `POST /agent/declaration-check {omit_tool:ontology.catalog}` → `TOOL_UNAVAILABLE` 出现 |
| 期望输出 | 同一事实、两份声明 → 两个结论；`flips` 非空 |
| 话术 | 「传统系统改口径要改代码发版；这里改本体声明，行为立刻翻转。」 |

### M2 状态机：已送达的运单还能改派吗？

| 项 | 内容 |
|---|---|
| 开场问 | 陌生人能接单吗？终态能改派吗？同一幂等键按两次执行几次？ |
| 本体声明 | `state_machines[Waybill].terminal`、`actions[].roles/from_status`、审计幂等键 |
| 正向 | `GET /ontology/state-machines/Waybill` → 终态声明摊开；`get_object` 的 `blocked_actions` |
| **负向翻转** | `POST /actions/lab`（SAVEPOINT）→ 错角色 `FORBIDDEN_ROLE`、错状态 `INVALID_STATE`、同键 `replayed=true` |
| 零污染 | `ROLLBACK` 后审计增量 0、状态还原 |
| 话术 | 「拦住动作的不是前端灰按钮，是本体里的状态机与角色声明，并且能在事务里实测。」 |

### M3 来源契约：这笔费用谁认领、缺什么证据？

| 项 | 内容 |
|---|---|
| 开场问 | 7 条费用都有源系统认领吗？删掉一条认领声明会怎样？ |
| 本体声明 | `data_sources[TMS].fee_types` 含 waiting / highway；`require_evidence` |
| 正向 | `GET /contracts/coverage` → 7 行、缺口 0 |
| **负向翻转** | `POST /contracts/simulate {case:drop_claim}` → `FEE_SOURCE_UNRESOLVED` 出现；`drop_source` → 6 条未解析 |
| 诚实补充 | `GET /ontology/abox-coverage` → 500 类只有 18 核心类有实例（能表达 ≠ 被证明） |
| 话术 | 「缺口不是算出来的 0，是本体声明定义的『谁负责』。删声明，缺口立刻暴露。」 |

### M4 权限：同一结论，不同角色看到的不一样

| 项 | 内容 |
|---|---|
| 开场问 | 匿名能看到几条？Agent 想把工单说出去，拦得住吗？ |
| 本体声明 | `data_source_markings[客服工单].marking = DISPUTE_OPS`、列级 marking |
| 正向 | `POST /enh/security/simulate` → 匿名可见 6/7 行 |
| **负向翻转** | `POST /enh/security/simulate-marking` → 删标记后可见 0→2；`guard-output` → 匿名 `OUTPUT_MARKING_DENIED` |
| 话术 | 「权限跟着本体属性走，一路传到 Agent 输出——是数据流的内建属性，不是页面开关。」 |

### M5 AI：凭什么不编？

| 项 | 内容 |
|---|---|
| 开场问 | 不给声明，AI 能凭空查吗？删掉 FeeItem 类型会怎样？ |
| 本体声明 | `primitives`（工具白名单）、`classes`（可圈定类型）、证据 checksum |
| 正向 | `POST /agent/declaration-check` → 工具 15、类型 500、evidence checksum |
| **负向翻转** | `omit_tool` → `TOOL_UNAVAILABLE`；`omit_type:FeeItem` → `TYPE_UNBOUND` |
| 最后一击 | `POST /reasoning-chain/start` 真实调用大模型（只在最后一幕） |
| 话术 | 「模型负责理解人话，本体决定它能看什么、能算什么。抽掉声明，链路确定性失败。」 |

### M6 收束：这单到底为什么贵 38？

| 项 | 内容 |
|---|---|
| 开场问 | 同一份数据直接丢给大模型，它算得对吗？ |
| 本体声明 | `pricing.waiting` 公式 + 版本 + 生效期 + 证据 checksum |
| 正向 | 规则应计 12 元、实收 25 元、超收 13 元，带证据链 |
| **裸系统对照** | 裸 LLM 答「应收 0、多收 25、凭不上」 |
| 话术 | 「差的 13 元不在数据里，在计价规则里。本体把规则变成机器可执行、可审计的东西。」 |

## 2. 四题深挖（页面折叠，领导追问时展开）

| 题 | 问题 | 核心件 | **负向翻转** |
|---|---|---|---|
| D1 | 改一个属性会波及谁？ | 属性级/对象级血缘、影响面 | 4097 节点/4129 边；属性 upstream/downstream 可查 |
| D2 | 改本体能不能像代码一样评审？ | 版本快照、签字、回滚 | `guard-demo drop_property_unsigned` → FAIL；`drop_property_signed` → PASS（临时签字目录，不写仓库） |
| D3 | 查业务语义，不查表名？ | Object Set、Ontology SQL、接口多态 | `interfaces/simulate` → 实现类 2→1、函数从接受到拒绝 `INTERFACE_VIOLATION` |
| D4 | 1961 个属性注册表真的执行吗？ | 属性注册表、写入门禁 | `type-lab` 把 `waiting_minutes` 改 boolean → 创建路径 `TYPE_MISMATCH` |

> 讲解口径：**交互演示展示本体怎么推理；操作演示（负向翻转）展示本体怎么被约束——后者才是企业愿意付钱的理由。**

## 3. ★ 补刀：把大模型放在同一份数据上对一次

```bash
python scripts/demo_coverage_audit.py
```

**实测原文（2026-11-21，可直接引用）**：

| | 裸大模型（给原始数据，不给本体） | 本体（`function.fee_breakdown`，0.01 秒） |
|---|---|---|
| 等候费按规则**应收**多少 | **0.00 元**（把 `quoted_amount=0` 当应计值） | **12.00 元**（`ceil(max(0, 53-30)/5)*2.4`，版本 2026.10） |
| 差额判断 | 多收 25 元，「**目前凭不上**」 | 应计 12 / 实收 25 / **超收 13 元**，附证据链 |
| 依据 | 无 | 规则 ID + 版本 + 生效期 + 证据 ID + checksum |

> 「差的 13 元不在数据里——在计价规则里：公式、版本、生效期、车型费率。」

**为什么问题要问成"数据里没有答案的那种"**：原来问「这单为什么多 38 元」裸大模型能答到七八成，
本体价值被稀释。改问**应计值、状态机前置、缺口语义**——这些只能靠声明回答。

### 3.1 ★★ 属性图对照：如果领导问"我用 Neo4j 能不能做"

把同一份数据喂给「**属性图 + 硬编码规则**」方案（networkx 构属性图，**禁止读本体声明**，
业务规则一律写死在服务代码里——这就是真实属性图项目的形态），同答 6 题
（脚本 `scripts/property_graph_parity.py`，日志 `logs/parity2_*.log`）：

| 题 | 属性图能答对吗 | 差别在哪 |
|---|---|---|
| Q1 这单为什么多 38 元 | **能，不输我们** | 图上拿 quoted/actual 相减即可 → **这题不构成差异，别当卖点** |
| Q2 等候费按规则应收多少 | 能，但**公式是硬编码常量** | 答案 12 元在数据里没有，在声明里 |
| Q3 减免 40 会挡住哪一步 | 能，但**状态机是三个硬编码 dict** | 且要与本体那侧保持一致 |
| Q4 高速费没人认领会怎样 | **答不出** | 缺口语义不存在于属性图方案 |
| Q5 报价三口径一致吗 | 能，但**「哪三个口径」是硬编码** | 换业务就要改代码 |
| Q6 改免费等候 30→20 | 能 | **改动位置不同**（见下） |

**最能说明问题的是漏改实验**：改免费等候 30→20，属性图方案若只改了诊断服务一处 →
**诊断说 16.8 元、预检说 12.0 元，两边结论打架，而且没有任何机制能发现**；
本体侧所有路径读同一份声明，**不可能漏改**。

**规模账**：把我们这套声明完整对齐到属性图方案，约需 **2968 行硬编码**，
且没有 schema 校验、没有门禁、没有承重保护；我们这边是 **1 处 JSON + 30 项门禁 + 24 条承重**。

> **演示口径（重要）**：不要用"我们能问答"当卖点——那是伪差异，一戳就破。
> 要用三件事：**① 答案在数据里没有时也能给（应计 12 元）；② 漏改不可能（一致性）；
> ③ 改一处全链路变（承重 24 条）。**

## 4. 领导可能问的（诚实口径）

| 问题 | 怎么答 |
|---|---|
| 「跟直接问大模型有什么区别？」 | 当场给 §3 实测：裸 LLM 说「应收 0、凭不上」；本体按规则应计 12、超收 13，带公式/版本/证据。本体 0.01 秒可复现，规则改动过门禁签字 |
| 「跟普通数据库/BI 的区别？」 | 数据答「是什么」，本体答「该怎么做、不能做什么、凭什么这么算」。「装货后还能改派吗」普通表查不出来 |
| 「数据量多大？接真实业务了吗？」 | **诚实**：500 类/503 链接/1961 属性/16 规则/15 动作；主链路 18 类有真实对象（全量 3.6%）。数据是剧本数据，下一步按契约接真实系统 |
| 「这不就是给表加注释吗？」 | 反例：注释写「等候费 12 元」不会随规则变化；本体有公式+版本+生效期，改报价规则时归因跟着变 |
| 「大模型答错了怎么办？」 | 三层：算钱不交给模型；结论带规则/证据/来源/版本可复核；口径冲突显式报；抽掉本体链路构造即失败 |
| 「能自动执行动作吗？」 | 动作先做前置校验，人工确认才写；写回有审计与幂等键。自动执行暂缓 |

## 5. 排他性口径（统一表述）

**不说「绝对只有本体能解决」**，统一为：

> 「**只给原始数据、不给本体声明时答不出来；改一行声明，行为立刻翻转**。」

六条主线都满足这个口径：M1 版本、M2 状态/角色、M3 来源认领、M4 marking、M5 工具/类型声明、M6 规则——缺任一声明，对应结论就出不来或翻转。
