## 1. 编制原则

1. **先解决本体知识怎么存、怎么查、怎么用**：canonical schema → 存储与数据源映射 → Object 查询与 Object Set → Agent 工具面；这是主线和关键路径；
2. **判断与提议建立在检索之上**：检索闭环稳定后再做只读 Judgment / Proposal，不作为第一阶段目标，更不能替代检索；
3. **Action 执行最后且不在范围**：只保留动作声明供提议引用，不做 apply / edits / 副作用 / 写回；P-07 明确暂缓；
4. **权限只为读与检索服务**：marking 约束可见范围，不阻塞检索主链路，不为写入口预留；
5. **物化按触发条件插入**：默认现查，投影与索引按基准 3.1 的触发条件再上；
6. **旧任务不删除、不重编号**：新增任务用 `G{批次}-{序号}`，通过“来源”列映射到原 `P{阶段}-{序号}`。

## 2. 优先关注点（知识存储 / 检索 / 使用）

```
TBox（类/关系/属性/数据源映射/规则声明）
  → 存储：canonical 定义 + 数据源映射 + 身份键（现查或投影）
  → 检索：Object 查询 / Object Set / search-around / 分页与一致性
  → 使用：Agent 工具面、catalog 注入与 token 预算、评测
  → 判断与提议：只读产出，作为检索闭环之上的增量
```

MVP 判定（freight「运单费用差异诊断」）：Agent 能定位对象、按关系与规则检索出完整上下文、给出带证据且可回溯的答案；判断/提议为后续增量；全程只读，不写业务数据。

## 4. 关键路径

```
G0-03 → G1-01 ─┬→ G1-05 ─┐
               └→ G2-01 ─┴→ G2-02 → G2-03 → G3-01 → G3-02 → G3-04

后续增量（非第一阶段）：
G3-01 → G4-03
G5-01 → G5-02 → G5-03 → G5-06
```

- 主线是知识存储与检索：G2-01 → G2-02 → G2-03，再进入使用与评测 G3；
- G4 读侧权限在工具面可用后接入，不阻塞检索；
- G5 判断与提议在 G2 / G3 稳定后启动，只读；
- 不在关键路径：G2-04~06（投影）、G4、G5、G6；
- Action 执行（apply / edits / 副作用）不在范围。

## 6. MVP 退出标准

- [ ] canonical schema + 存储与数据源映射规范落地，`validate` 接入 CI；
- [ ] Object Set 支持 search-around 与分页，结果不重不漏；
- [ ] Agent 能稳定定位对象并检索完整上下文，评测集达标；
- [ ] 检索与使用的可观测链路可回溯；
- [ ] 权限可拦截越权，marking 传播有回归用例；
- [ ] 发布快照可回滚。
