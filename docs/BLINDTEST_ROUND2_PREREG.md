## 2. 第 2 轮判据（事前注册）

### 2.1 主判据：层级归属正确性（新增）

**指标 H1：组对一致性（pairwise agreement，看分组结构、不看组名）**

在可比集 `S`（见 2.2）上：

- `P_h = {(a1,a2) ⊂ S : 人工组相同}`（人工同类对）
- `P_l = {(a1,a2) ⊂ S : LLM 组相同}`（LLM 同组对）
- **J（H1 主值）= |P_h ∩ P_l| / |P_h ∪ P_l|**（组对 Jaccard）
- 辅报：precision = |P_h ∩ P_l| / |P_l|、recall = |P_h ∩ P_l| / |P_h|

**为什么看结构不看组名**：人工组 id（`vehicle_domain` 等）是我方自定的，
LLM 从业务口语**不可能知道这些 id**；若直接比名字会造出必然失败的假指标。
只看"哪些类被归到同一组"才是模型真正能做、也真正该被评价的事。

**判定（四条全过才算通过）**：

| # | 条件 | 阈值 | 依据 |
|---|---|---|---|
| H1-a | **非退化** | LLM 用的组数 ≥3 **且** 最大组占比 ≤0.60 | 见 §3：退化"全塞一组"在 Jaccard 上反而高达 0.33~0.58，必须先拦 |
| H1-b | **结构一致性** | J ≥ **0.30** | 随机基线：均衡随机分组 J 均值 0.11~0.14、p99 0.16~0.19（§3）⇒ 0.30 ≈ p99 的 1.6~2.7 倍 |
| H1-c | **显著性** | 置换检验 p < **0.01**（B=2000，置换人工组标签） | 零分布同 §3 |
| H1-d | **最小样本量守卫** | 可比集 \|S\| ≥ **20**，否则该指标**不出判定**（报"样本不足，判据不适用"） | \|S\|<20 时组对数量过少，Jaccard 噪声大于信号 |

**指标 H2（辅助，不设判据）**：业务板块命中率——把 LLM 的组名经**别名表**映射到人工 6 组后，
命中正确板块的类数 / 可比集大小。别名表由人构建（见 §5），带主观性 ⇒ 只报告、不参与判定。

### 2.2 可比集 `S` 的定义（两档，都要报）

| 档 | 映射规则 | 用途 |
|---|---|---|
| **宽（主）** | LLM 类 → 人工类 用**语义对应**映射，相似度 ≥ **0.40**（相似度 = 0.5×名称 bigram Jaccard + 0.5×属性集 Jaccard，与第 1 轮诊断脚本同式） | **判据只看这档** |
| 严格（敏感性） | 仅用**精确名匹配**（label 中文精确 → id 精确 → label 归一化，与第 1 轮同规则） | 只报告，不参与判定 |

★ 宽口径的理由：层级测的是"归类对不对"，**命名差异不该被惩罚**（第 1 轮语义对应率 46.9% 显著高于
精确名 25.5%，正说明命名差异是主要失分来源）。用 0.40（高于第 1 轮诊断的 0.25）以压低误配。
★ 宽口径的已知弱点：语义映射本身可能误配 ⇒ 因此**严格口径必须同时报告**（若两档结论相反，
以宽口径判据为准、但必须在报告里显式标注分歧）。

### 2.3 复现观察项（不设判据，第 1 轮已测）

  但**第 2 轮不以它们为判据**——第 1 轮结论已冻结）
- 公理：state_machine 声明率 / 初态命中 / 终态命中 / 状态集 Jaccard（**观察**，不判定）

★ 为什么公理不设判据：第 1 轮已测得（0% / 14.3% / 21.4%），若现在据此定阈值即**用已见数据定线**

### A.2 失效归因（为什么 FAIL 不等于"模型不会建层级"）

模型给出的 15 个组（全部 group 字段，117/117 覆盖）：
`保养管理、保险理赔、充电设施与记录、加油卡与充值、加油站与油价、变更争议、合作合同、
审批与单据、承运商主体、线路分包、维修管理、证照资质、车辆权属、车辆档案、配件采购`

对照人工 6 组（**主体域维度**：`vehicle / carrier / driver / maintenance / fuel / subcontract`）：

| 人工组 | 模型对应组 | 形态 |
|---|---|---|
| vehicle_domain | 车辆档案 / 车辆权属 / 证照资质 / 保险理赔 / 配件采购 | **1 个主体域被拆成 5 个主题组** |
| carrier_domain | 承运商主体 / 合作合同 / 审批与单据 / 变更争议 | **拆成 4 个** |
| maintenance_domain | 维修管理 / 保养管理 | 拆成 2 个 |
| fuel_domain | 加油卡与充值 / 加油站与油价 / 充电设施与记录 | 拆成 3 个 |
| subcontract_domain | 线路分包 | 1 个 |
| driver_domain | **无** | **主体域整体缺失** |

⇒ 三条读数互相印证同一件事：

1. **precision 0.92**：模型**几乎从不错分**——它判为同组的类，几乎都是人工同一主体域的类。
2. **recall 0.27**：但它把人工一个主体域**拆细成多个主题/流程组**，导致人工同类对大半失配。
3. **模型用的是另一个划分维度**：**业务主题/流程维度**（主题维度），
   而人工 6 组用的是**业务主体域维度**（主体维度）——两者不冲突，只是**切法不同**。

⇒ ★ **因此 H1 的 FAIL 不能推出"模型不会建层级"**。可推出的只有：
**模型建的层级与我方层级在结构上不一致（维度不同 + 粒度更细 + 漏一个主体域）**。

★ 这与外部实证同源（`docs/ARTICLE_20261126_CROSSCHECK.md` §4.2）：
"推理补不回层级"——层级的核心是**维度选择**（业务语义判断），闭包/推理救不了"维度选错"。
模型能建分组，但它**猜**维度；维度猜错时，分组本身再合理也不等于本体的层级。

⇒ H2（板块命中 56%、未映射 10）也是同一原因：别名表是**人工 6 组视角**，
主题维度组名（"证照资质""保险理赔"…）映射不进去 ⇒ H2 系统性低估，不作"归错"解读。
