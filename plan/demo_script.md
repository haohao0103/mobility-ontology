# 本体系统演示脚本（后天 · 面向领导）

> 目标：**让领导在 20 分钟内看懂「本体系统有哪些东西」+「交互式提问能不能展示它的价值」**
> 环境：本地部署（STG `stg-121` 当前不可达）。端口以实际启动为准：
> `python cli.py serve --port 8799` → 页面 `http://127.0.0.1:8799/profile/order-ontology`
> 演示前必跑：`DEMO_BASE=http://127.0.0.1:8799 python scripts/demo_gate.py`（全绿再上台）

## 0. 开场 30 秒（先把"本体"这三个字说清楚）

> 「这系统的核心不是一张表，是一个**本体**：我们把'运单、费用项、定价规则、报价单、结算单'
> 这些业务概念连同它们之间的**关系、规矩、状态流转和能做的动作**一起定义在一处。
> 大模型可以读它、Agent 可以按它推理、系统可以按它拦得住不该做的事。
> 接下来我会带大家看三件事：**它里面有什么**、**它怎么回答业务问题**、**它怎么保证答案可信**。」

**不要说**"这是一个图数据库"（领导会理解成可视化工具），**要说**"这是一套让机器理解业务规则的本体"。

## 1. 本体系统里到底有什么（回答"有哪些东西"）

页面里已有分区，按这个顺序讲（每项 20~40 秒）：

| # | 讲什么 | 页面位置 | 一句话价值 | 背后可验证的机制 |
|---|---|---|---|---|
| 1 | **有哪些东西** | 「有哪些『东西』？」 | 500 个对象类型：运单、费用项、报价单、结算单……每个都有**主键、状态、属性白名单、责任人、图标** | `semantic_layer.json` + 属性注册表（1961 个属性，类×属性 3527 组合 0 未注册） |
| 2 | **它们怎么认识** | 「它们怎么『认识』？」 | 503 条**带基数**的关系：运单产生费用、费用按规则计价、费用进结算 | 关系两端受 domain/range/cardinality 约束 |
| 3 | **什么不能做** | 「什么『不能』做？」 | 类型、状态、属性都有约束：写入即校验，非法数据进不来 | 写入侧类型执行 + 门禁 28 项 |
| 4 | **能做什么** | 「能『做什么』？」 | 15 个**动作**（接单、改派、申诉、减免、冲正、红冲…）带**前置状态、角色、参数** | 状态机 + 动作执行 + 审计 + 幂等 |
| 5 | **怎么算钱** | 规则与函数区 | 费用不是写死的，是**本体里的规则算出来的**：等候费 12 元怎么来的，公式在本体里 | 16 条规则（AST）+ 4 个确定性函数 + 报价三口径互校 |
| 6 | **怎么保证可信** | 治理区 | 改本体要过门禁：破坏性变更必须签字，**只改 JSON 不改代码**行为就会变 | 门禁 28 项 + 承重实验 24 条 |

> **对比叙事（页面里已有，强烈建议用）**：页面并排放了「把表改个名 / 画一张 ER 图 / 建个图数据库 /
> 写本数据字典」四条常规做法，然后指出它们的共同问题——**都只描述了数据长什么样，
> 没描述业务能做什么、不能做什么、凭什么这么算**。本体补的就是这一层。

### 1.1 审计结论：三个核心要素没被任何交互式问题触及（用"操作"补，不要用"提问"补）

2026-11-21 的覆盖审计（`scripts/demo_coverage_audit.py`）实测：三个演示问题触及了
**8~11 个类、160~199 个本体项、14/16 条规则、7/7 种费用类型**——
**规则、关系、状态机、动作、函数、费用类型都被串起来了**。但有三个 Palantir 最具特色的要素，
**没有任何交互式问题能问到**，必须用**操作**演示：

| 要素 | 为什么问不出来 | 用什么操作演示（页面区块） |
|---|---|---|
| **标记与强制访问控制**（3 标记 / 1 行级 / 2 列级 + 传播） | 这是"行可见性"问题，不是"业务知识"问题，提问问不出来 | 页面「策略测试器（对标 Test policies）」：切身份看同一批费用——匿名视角只见 6 项、DISPUTE_OPS 标记视角见全量 7 项，差额可见但行被静默过滤；列级 PII/FINANCE 属性对无标记用户直接置 null |
| **接口与多态**（3 接口 / 33 实现） | 提问不会自然触发"按接口自动路由" | 页面「接口 → 实现者 → 多态函数」：同一个 `accepts_interface` 函数，传入不同实现类**自动路由到不同实现**，新增实现类零代码接入 |
| **变更治理**（门禁 28 项 / 承重 24 条 / 破坏性变更签字） | 演示时改本体等于现场搞破坏 | 页面治理区展示门禁与承重实验结论；**若领导追问"改了会不会出事"**，再当场演示一次"改本体 → 门禁 FAIL" |

> 讲解口径：**「交互式提问展示的是『本体怎么推理』，操作演示展示的是『本体怎么被约束』——
> 后者才是企业愿意付钱的理由」**。

## 2. 交互式提问：能不能展示价值（演示核心）

### 2.1 问题设计：只问「数据里没有答案」的问题

> **2026-11-21 实证审计的结论（重要）**：原来的三个问题「为什么多 38 元」「高速费谁认领」「凭证是哪条」
> **不够不可替代**——把原始数据喂给裸大模型，它能答到七八成（见 §2.3 的实测对照）。
> 演示若用这种问题，领导自己拿 ChatGPT 一试就会发现"它也答得不错"，本体价值被稀释。
> 因此改成下面这组：**要么答案不在数据里，要么必须过本体才能拿到。**

| 编号 | 怎么问 | 答案里必须出现（本体独有） | 裸 LLM 答不出的原因 |
|---|---|---|---|
| **A′ 应计 vs 实收** | 「这笔等候费按规则应该收多少？实际收了多少？多收的部分凭什么？」 | **应计 12.00 元 / 实收 25.00 元 / 超收 13.00 元** + 公式 `ceil(max(0, 53-30)/5)*2.4` + 规则版本 2026.10 + 生效期 10-01~12-31 + 车型费率 | 公式不在数据里。裸 LLM 只会答「按规则应收 0 元（报价口径），多收 25，凭不上」——**把报价当成了应计值** |
| **B 假设推演** | 「如果给客户减免 40 元，系统接下来会发生什么？会挡住哪一步？」 | 减免落在 `fee:F003`；`waive_charge` 预检通过（DISPUTED→WAIVED）；**结算已入账不能挂起、只能冲正**；动作只提案不落库 | 状态机前置、角色、动作契约都不在数据里。裸 LLM 会陷入算术（40 > 25），给不出系统行为 |
| **C′ 无人认领会怎样** | 「如果这条高速费没有任何系统认领，系统会怎么发现？会拒绝入账还是静默算成 0？」 | 缺口码语义：`FEE_SOURCE_UNRESOLVED`（无人认领）/ `FEE_SOURCE_TYPE_UNDECLARED`（口径越界）/ `FEE_SOURCE_STALE`（过期）/ `FEE_EVIDENCE_MISSING`（缺证据）——**取不到会报缺口，不会静默算 0** | "无人认领"是**本体语义**，裸表里只是一列 source_system；裸 LLM 根本不知道系统还有"发现缺口"这个机制，会跑去核对数据 |

**A′ 的演示方式**：**先走确定性接口**（`function.fee_breakdown`，0.01 秒，逐项给出 报价 / 应计 / 实收 三列 + 公式 + 依据链），
再问 B、C′ 走自然语言。
理由：实测 A′ 问法会让模型绕 22 步、用尽工具预算 → 结论降级成"初步结论"，不稳。**应计值本来就该由本体算，不该让模型现算。**

### 2.2 交互的两个事实（主动说，别等领导问）

| 事实 | 数字 | 怎么讲 |
|---|---|---|
| 自然语言问答要 **45~90 秒** | 14~22 步、5 类参与方（实测 44.5s / 61s / 74s / 89s） | "它不是一次问答，是**在本体上走了一趟**：规划→查类型→决策→取事实→套规则→提动作→汇总结论" |
| 同一问题，**确定性本体路径 0.01 秒** | fee_breakdown 0.01s | "**算钱的部分我们用本体做死（可复现、可审计），理解人话的部分才交给大模型**" |

> 这两个数字放在一起讲，反而是**最强的一击**：不是"我们也有个大模型"，而是
> **"算钱的部分我们用本体做死（可复现、可审计），理解人话的部分才交给大模型"**。

### 2.3 ★ 现场对照实验（最有说服力的一个动作，建议保留）

把**同一份原始数据**分别交给「裸大模型」和「本体」，当场对比（可复现）：

```bash
python scripts/demo_coverage_audit.py     # 内含对照 A（裸 SQL）与对照 B（裸 LLM）
```

**现场话术**：
> 「我刚才把同一份数据直接丢给大模型，它说：等候费按规则应收 **0 元**、多收 **25 元**、'目前凭不上'。
> 本体给的是：按 R-WAIT-01（版本 2026.10）**应计 12 元**，实收 25 元，**超收 13 元**。
> 差的 13 元**不在数据里**——它在计价规则里：公式、版本、生效期、车型费率。
> 这就是本体系统的价值：**把规则变成机器可执行、可审计的东西**，而不是每次靠人记住或靠模型猜。」

**实测原文（2026-11-21，可直接引用）**：

| | 裸 LLM（给原始数据，不给本体） | 本体 `function.fee_breakdown` |
|---|---|---|
| 等候费按规则应收 | **0.00 元**（把 `quoted_amount=0` 当应计值） | **12.00 元**（`ceil(max(0,53-30)/5)*2.4`） |
| 差额判断 | 多收 25 元，「**目前凭不上**」 | 应计 12 / 实收 25 / **超收 13**，并附证据链与生效期 |
| 高速费来源 | 能答（ETC / fee:F004）——**这题不构成差异，别用** | 同上，但额外有归属唯一性与缺口语义 |

| 时间 | 动作 | 说什么 | 证明什么 |
|---|---|---|---|

| 7:00 | ★ **现场对照实验**（§2.3） | "同一份数据裸大模型说『应收 0、多收 25、凭不上』" | **不可替代性** |
| 10:00 | **B 假设推演**（自然语言，一键跑到底） | 减免 → 只能冲正 → 发票红冲 → **动作只提案等人确认** | 本体独有的状态机与动作契约 |

| 15:00 | **操作演示**：策略测试器（切身份看行级/列级） | "同一批费用，匿名只见 6 项、标记视角见 7 项" | **强制访问控制**（交互问题问不出来的部分） |
| 16:30 | **操作演示**：接口 → 实现者 → 多态函数 | "换实现类，函数自动路由，零代码" | **多态** |
| 17:30 | 治理区：门禁 28 项 / 承重 24 条 | "改本体要过门禁，破坏性变更要签字" | **不是玩具** |
| 18:30 | 收尾 | "下一步：把这 18 个类型逐个接到真实业务系统" | 路线清晰 |

**顺序的关键**：
1. **先快后慢**——先用 0.01 秒的确定性路径建立"这东西是真的"，再上 45~90 秒的自然语言做高潮；
2. **对照实验放在自然语言之前**——领导先看到"大模型也答得不错"，再看到"本体答得更准且可审计"，
   冲击力比先自夸强得多；
3. **交互演示放中间，操作演示放后面**——交互证明"会推理"，操作证明"受约束"，企业更在意后者。

## 4. 领导可能问的（准备好答案）

| 问题 | 怎么答（诚实口径） |
|---|---|
| 「这跟普通数据库 / BI 报表的区别是什么？」 | 数据能回答"是什么"，本体能回答"**该怎么做、不能做什么、凭什么这么算**"。比如"装货完成后还能改派司机吗"——普通表里查不出来，状态机里一句话给答案 |
| 「跟直接问大模型有什么区别？」 | **当场给实测**：「同一份数据，裸大模型说等候费『应收 0 元、多收 25、凭不上』；本体说『按 R-WAIT-01 应计 12 元，超收 13 元』，还带公式、版本、生效期与证据链。差的 13 元不在数据里，在计价规则里。」**另外**：本体路径 0.01 秒且结果可复现，大模型每次可能不同；本体的规则改动会被门禁拦住并要求签字 |
| 「数据量多大？接入真实业务了吗？」 | **诚实**：本体定义了 500 个类型，但当前只有**主链路 18 个类型**有真实对象（深水区 100% 覆盖；全量 3.6%）。数据是**剧本数据**，用于验证机制；下一步就是把真实系统按 `data_sources` 契约接进来 |
| 「这不就是给表加了注释吗？」 | 给个反例：注释说"等候费 12 元"，本体里有**公式**（等待 45 分钟 - 免费 30 分钟，向上取整到 5 分钟块，2.4 元/块）；改报价规则时，**差额归因会跟着变**，注释不会 |
| 「大模型答错了怎么办？」 | 三层防线：① 算钱不交给模型（规则在本体，模型只负责理解问题）；② 每个结论带规则/证据/来源，可复核；③ 结论不一致会**报口径冲突**，不静默取一个 |
| 「能不能自动执行动作？会不会误操作？」 | 现在是**只提案不执行**：动作先做前置校验（状态/角色/规则），人工确认才写；写回有审计和幂等键。自动执行是我们明确**暂缓**的部分（矩阵 P-07） |
| 「这套能给我们带来什么？」 | 落点建议：**新业务上线时不用再口头对齐规则**——规则、状态、动作写在一处，Agent 与人用同一套；改一处，所有入口同步生效，且改动要过门禁签字 |

## 5. 风险与兜底（现场出问题怎么办）

| 风险 | 征兆 | 兜底 |
|---|---|---|
| **LLM 不通 / 抖动** | 推理链报错或卡住 | **系统已内建三层保险**：① 指数退避重试（429/5xx/网络抖动/空响应，401/403 不重试）；② 模型输出格式不规范时宽松收下；③ 工具预算用尽或大模型彻底失败时**降级成"初步结论"而不是 503**。即便如此仍失败，就**切确定性路径**：fee-analysis / explain / 状态机 / 动作预检全是 0.1 秒级、**完全不依赖大模型**。顺势讲："**这就是本体的价值——结论不依赖外部模型**" |
| **页面打不开 / 渲染异常** | 白屏 | 切 REST：`/docs`（Swagger）与 `/freight/ontology`、`/freight/ontology/state-machines` 都能看 |
| **问题问偏了 / 答不出** | 答案泛泛 | 换到 §2.1 的三个问题（已验证有效）；或反问"要不要看我把这个过程拆开"→ 打开「下一步」逐步展示 |
| **等待焦虑（70 秒）** | 领导盯着空白 | 先点「下一步」逐步走，边走边讲每一步在干什么；或者提前说一句"它要自己查一轮，大概一分钟" |
| **端口被占 / 服务没起** | demo_gate 报 FAIL | `lsof -nP -tiTCP:8765 -sTCP:LISTEN \| xargs kill` 后重启；**上台前 5 分钟不要再重启服务** |
