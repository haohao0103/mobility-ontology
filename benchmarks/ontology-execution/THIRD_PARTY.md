# 第三方实现邀请

> 我们需要**1~2 位没有参与本基准设计的人**，按协议独立实现「属性图 + 服务代码规则」路线。
> 这是本基准**能否被信任**的关键一步 —— 内置参考实现由我们自己写，存在稻草人风险。

## 1. 为什么找你

内置的属性图参考实现由本基准作者编写：它可能**并不能代表一个认真做的属性图方案**。
如果最终结论是"本体路线更好"，最容易被质疑的一句话就是——
「**你们自己的属性图实现是不是故意写差的？**」

独立第三方实现是解掉这个质疑的唯一办法。

## 2. 你要做什么

按 [PROTOCOL.md](PROTOCOL.md) §1 的接口契约，实现一个类，提供六个方法：

```python
class MyPropertyGraphImpl:
    def q1_diff(self, waybill_id="WB20261105001") -> dict: ...
    def q2_waiting(self, waybill_id="WB20261105001") -> dict: ...
    def q3_roadblock(self, amount=40.0, waybill_id="WB20261105001") -> dict: ...
    def apply_change(self, card: dict) -> dict: ...
```

材料（**只有这些**）：

- [PROTOCOL.md](PROTOCOL.md) —— 契约、公平性铁律、判定口径、指标定义
- `data/` —— 中立数据集（2 张运单 / 8 条费用 / 声明 / 3 张变更卡）
- `starter/` —— 空白起步骨架（只有 TODO，没有实现逻辑）

**不要看** `implementations/` 里我们写的两个参考实现 —— 看了就被污染了，
你的实现就不再是独立第三方的。评测器会做静态隔离检查（见 §4）。

## 3. 公平性的几条硬约束

1. **只依赖标准库**（或你习惯的第三方库，但要在提交里说明）；
2. **不得读取** `manifest.json` 里的期望值（评测器会静态扫描）；
3. **不得 import** 本基准作者的私有包、不得读 `semantic_layer.json`；
4. 业务规则放在**你的工程目录里**（评测器会把你的目录复制到工作区，改动不会污染源码）；
5. 变更卡由评测器下发，你只能通过 `apply_change` 声明改了什么。

## 4. 隔离检查（评测器会自动跑）

```
python runner.py --impl /path/to/your_impl.py --audit-impl
```

会检查：

| 检查 | 判定 |
|---|---|
| 源码里出现 `manifest` / `golden` / `expects` / `expected` | **失败**：不得偷看期望值 |
| 源码里出现 `import freight` / `semantic_layer` | **失败**：不得使用作者私有能力 |
| import 了非标准库 | 提示（不失败，但要在提交里说明理由） |

## 5. 怎么提交

1. 把实现放进 `implementations/<你的名字>/`（或直接给一个 `.py` 文件路径）；
2. 在 README 的结果表里加一行（`python runner.py --json` 的输出即可）；
3. 提交一个 PR，附上：
   - 你的实现思路（**尤其是**：费率参数放在哪、金额上限怎么表达、车型怎么参与计算）；
   - 你在实现中遇到的**判断题**（例如"上限口径用配置还是代码"以及为什么）；
   - 任何你认为本协议不公平的地方。

## 6. 评审标准（我们会按这个评）

见 [REVIEW_CHECKLIST.md](REVIEW_CHECKLIST.md)。要点：

- **不是"越强越好"**：属性图路线的目标是"**认真实现的属性图方案**"，
  不是"最强的属性图方案"。把它写得比本体强反而说明基准不中立；
- 凡是能交给配置/声明的，就不要硬编码在代码里；反之亦然 —— **你要模拟真实项目里
  该团队会怎么做**，而不是按我们的偏好做；
- 如果你认为某个用例的期望值本身不合理，**请在 PR 里说明** —— 我们会讨论并可能改基准。

## 7. 时间与回报

- 工作量：一个下午（不必写生产级，**要诚实**）；
- 回报：你的名字会出现在结果表与引用里；这份基准会公开，**你写的实现是它的第一批独立证据**；
- 如果你的实现跑出来**赢过**内置参考实现，我们会照实更新基线并写进 README。

## 8. 联系方式

在本仓开 issue：「我要提交一个实现」，或直接联系基准作者。
