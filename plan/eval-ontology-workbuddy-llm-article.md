# 评价：《Ontology+WorkBuddy+LLM——没学本体论的可以不学了》的可落地真实性

> 日期：2026-11-23｜评估对象：闭雨哲（北京图特摩斯科技）公众号文章，2026-11 前后发布
> 方法：不看宣传语，只看三件事——**技术主张有没有内涵、给的证据是什么等级、有没有可证伪的验收**
> 参照系：作者自家 OntoFlow/OntoGraph/OntoOS/OntoX 公开文档 + Palantir 官方文档 +
> 2026 年行业侧的公开数据（demo ceiling、企业 AI 试点失败率、Polsia 实验）

## 0. 一句话结论

**技术主张有真东西，证据等级是演示级（demo），但文章用生产级语言描述它。**
文章缺的不是能力，是**验收**——它自己那句"先不管它对不对、准不准、完整不完整"，
恰好把要证明的东西全部让掉了。

## 1. 文章里**真实且有含金量**的部分

| 主张 | 判断 |
|---|---|
| 「AI 能在一小时内搭出本体应用骨架」 | ✅ **可信**。我们自己就是这么干的（几天内做出 8 幕演示页 + 26 条断言的彩排脚本）。生成端成本被打到地板，是真的 |
| 「工业场景是本体最对口的战场（实体-组件-系统-流程）」 | ✅ **对**。Palantir 的主力客户也是工业/制造/能源；工业现场天生是"对象+关系+状态+规则+计算+行动" |
| 「AI for FDE（Forward Deployed Engineer）」 | ✅ **是真打法**。Palantir 自己就这么干，不是新概念 |
| OntoGraph 的多维本体（静态事实对象 / 单体动态对象 / 立方动态对象） | ✅ **有内涵**，是认真的建模方法论，不是词汇堆砌 |
| 「关系回归业务骨架，新增指标不撑大架构」 | ✅ **对**，这正是知识图谱「扁平化建模」的真痛点，他们抓准了 |
| 数据处理节点做「口径统一」（SMT二线 / SMT-02 / SMT-2 是同一台设备；快照 vs 增量） | ✅ **和我们做的事同类**。我们做的是「三口径互校 + 来源归属唯一」，他们做的是「别名合并 + 快照识别」——**同一类真问题，不同层面** |
| 推演分支**不写回**、真改动要**人工确认**才走 Action | ✅ **懂行的标志**。我们做的是「动作先提案不执行」，同构 |
| 明确写使用边界：「不派工、不开工、不领料、不放行」 | ✅ **加分项**。愿意写"我不做什么"的，比吹全能的可信 |

> 结论：**这不是纯营销文章**。他们确实懂本体，而且踩过坑（从 AbutionGraph 图数仓 → OntoGraph 本体原生库，
> "成也图谱，败也图谱"那段是真做过项目的人写的）。

## 2. 不可信 / 未验证的部分（附行业证据）

### ① "完整功能的本体应用" —— 文章自己把这句话收了回去

原文：「**我们先不管它对不对、准不准、完整不完整**，这是下一步与客户专家交流后就能知道的结果」。

**那就不能叫"完整功能"**，只能叫"可演示的骨架"。
这正是行业里被命名的 **demo ceiling**：
> Labarna AI《Engineered to Survive》：chat prompt 几分钟产出一个"看起来是整个业务操作系统"的东西——
> **「它不是。它是一张平台的图片。」** 而 demo 里看不到的失败场景包括：
> 进度款算错、病人看到别人的病历、货件过夜丢失、**审计问"谁批的这次变更"**、**离职员工仍持有系统访问权**。

### ② 全程**没有一张"业务专家验收通过"的证据**

所有截图都是：生成物（本体模型图）、工作流画布、看板、应用界面。**没有一张是"客户专家抽检通过"的记录**。

行业数据（2026）：
- **80~87% 的企业 AI 试点停在试点阶段**（Gartner / McKinsey / MIT Sloan 口径）
- Polsia 用 9 个 AI agent 开了 **283,381 家公司**，**94% 已死**，只有 16,447 家活跃（5.8%），首月流失 50%，Trustpilot 1.9/5
  → 差的那一步不是执行能力，是**"没人验货"**
- 有案例：48 小时的 HR 政策助手 demo 惊艳全场 → 9 个月后、$850,000 后被静默下线

**我们的直接对照**：我们自己的 500 类本体里，**只有 18 类有真实对象（全量 3.6%）**——
**没有业务对象来源的本体，就是一份自动生成的、看起来很像的目录。**
"一小时出本体"的真实代价不是建模时间，而是**后面每一个业务对象都要有人谈**。

### ③ "1 小时 + 45 元"是**演示成本**，不是**系统成本**

对照实验（zooz，24 小时 AI 建公司）：$67 花完，得到——落地页能用、12 个注册、**$0 收入**、
自治运作约 **35%**、需要持续人工干预；失败模式包括**幻觉复合**（营销 agent 声称"已排期发布"，
实际没排；这些假事实写进共享上下文，后续 agent 当真事实用）、**缺乏主动性**、**级联错误**。

Labarna 讲的第二道坎：从 demo 到能运转的系统，要接真实数据、外部系统、API 化的 agent，
**每一次检查、重试、恢复都按 token 计费**。

→ 所以"45 元"这个数字**恰好证明了生成成本已经归零**，但同时说明**它只覆盖了生成那一段**。

### ④ "Palantir 底层国产替代" —— 目前**没有证据**，而且他们自己也没敢这么比

- 他们给的是**功能清单**（分布式·流式·时序·空间·向量·图谱·函数·行动·派生·权限·时间演化·Agent…）：
  **清单不可验证**，且把"图数据库能力"与"本体能力"混在一起。
- 更有说服力的是他们**自己官网的对比表**：Palantir 那一列写的是"企业级、投入门槛高"，
  自己那列写"轻量起步、开发友好"——**用对手的产品形态说自己强，不构成替代证据**。
- 真要主张替代，需要的是**同场景对标**：同一份业务、同一批问题、同一套验收标准。
  **这正是我们这两天做的 `ontology-execution` 基准要做的事**（同题同数据、客观判定、
  公开可复现），也是我认为这类宣称唯一该被接受的方式。

### ⑤ "睡醒了！数字孪生有了～" —— 这是最容易被"可视化动画"伪装的部分

数字孪生的最低门槛是：**状态演化 + 事件 + 时间线 + 约束**（状态不对时会怎样？谁改的？能不能回放？）。
文章里**没有一句提到"改错数据会怎样"**。一个能动的看板和一个受约束的孪生，在截图上长得一样。

## 3. 我的技术判断（分开说公道话）

**他们不是骗子**：多维本体建模、派生、推演沙盘、MCP/Skill 接入、敢写使用边界 ——
这是真懂本体的人在做的事，而且和我们做的是**同一个方向**。

**真正的问题是证据等级与措辞不匹配**：
- 他们给的是**演示级证据**（生成物 + 看板截图）
- 却用**生产级语言**描述它（"完整功能的本体应用""数字孪生有了""Palantir 国产替代"）

这不是吹牛的问题，是**验收标准缺失**的问题。而缺验收正是行业 80~87% 失败的直接原因。

## 4. 这类项目该怎么验：三个我们已经在用的验收（缺一不可）

结合我们这两天做的事（承重 24 条 / 漏改实验 / 诚实性扫描 / 三方基准），给出**可操作的验收清单**：

| # | 验收 | 怎么测 | 不通过说明什么 |
|---|---|---|---|
| **① 承重** | 改本体声明、**代码零改动** → 行为必须翻转（**包括"从此被拒绝"**） | 24 条用例逐条跑 | 行为不变 ⇒ **规则其实藏在代码里**，本体只是文档 |
| **② 漂移** | 同一业务语义**只有一处**吗？改一处会不会两边打架？ | 静态数副本 + 漏改探针 | 我们实测过属性图方案：改参数漏一处 → **诊断说 16.8 / 预检说 12.0，无人察觉** |
| **③ 负面用例** | 错误数据 / 非法状态 / 越权角色**当场被拒**吗？边界写出来了吗 | 5/5 类非法输入当场拒绝 | 拒得晚 ⇒ 脏数据已入库，下游已在用它算账 |

**附加一条**：**业务专家抽检**——随机抽 N 条业务对象，让专家判定"这个对象和这个关系对不对"。
**没有这一步，前三条全过也只是"自洽"，不是"正确"。**

## 5. 对我们自己最有价值的四条（这部分比评价他更重要）

1. **方向被正面验证了**：一家有 10 年积累的公司、独立选择了"可执行本体 + FDE + AI 辅助建模"这条路——
   说明我们的方向不是拍脑袋。
2. **我们的差异化必须是"可证伪"，不是"我们也有本体"**：他们会很快也有本体模型图、应用、智能体。
   我们的护城河只能是**能当场证伪**（负向翻转、承重、漂移检出、公开基准）。
3. **应用层是共同短板，而且是我们更严重的短板**：他们有 OntoX（用户层孪生可视化）+ OntoOS（推演），
   **我们没有面向业务角色的应用层**——这与我前两天说的"我们 500 类只有 18 类有真实对象"是同一件事的两面。
4. **我们的证据等级其实比这篇文章高**：我们的 8 幕演示每一步都带**真实接口 + 声明依赖脚注 + 负向翻转**，
   彩排 26 条断言全绿；这篇文章从头到尾**只有正向截图**。
   → 对外时不要跟他比"做得快"，要比"**证得伪**"。

## 6. 给读者的一句话判据

> 「**看它敢不敢让你改一处声明、然后当场证明行为变了。**
> 能演示不改变任何东西，只能证明它长得像；能证伪，才证明它是真的。」

以及 2026 年行业公开数据与实验报告；未做付费产品实测，故对产品本身不作性能结论。）
